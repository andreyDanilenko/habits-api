# Чек-лист приемки CRM-модуля (Системный анализ)

## Методология проверки
- **Уровень тестирования**: Системное/интеграционное тестирование
- **Фокус**: Бизнес-процессы, целостность данных, ролевая модель
- **Тип проверок**: Функциональные + Нефункциональные требования

---

## Блок 1: Управление контрагентами (Counterparties)

### 1.1 Контакты (Contacts)
- [ ] Создание контакта с минимальными данными (имя + фамилия)
- [ ] Создание контакта с полными данными:
  - [ ] Имя, фамилия, отчество
  - [ ] Должность
  - [ ] День рождения
  - [ ] Теги
  - [ ] Ответственный (owner)
- [ ] Добавление нескольких телефонов к контакту:
  - [ ] Разные типы (рабочий, мобильный, домашний)
  - [ ] Возможность отметить основной телефон
- [ ] Добавление нескольких email к контакту:
  - [ ] Разные типы (рабочий, личный)
  - [ ] Возможность отметить основной email
- [ ] Привязка контакта к компании (company_id)
- [ ] Редактирование контакта с обновлением updated_at
- [ ] Удаление контакта (soft delete с deleted_at)
- [ ] Восстановление удаленного контакта
- [ ] Поиск контакта по имени, телефону, email
- [ ] Фильтрация контактов по тегам, ответственному, компании
- [ ] Экспорт списка контактов (CSV/Excel)

### 1.2 Компании (Companies)
- [ ] Создание компании с минимальными данными (название)
- [ ] Создание компании с полными реквизитами:
  - [ ] ИНН/КПП/ОГРН
  - [ ] Телефон, email, сайт
  - [ ] Юридический и фактический адреса (JSONB)
  - [ ] Теги
- [ ] Привязка нескольких контактов к компании (many-to-many)
- [ ] Указание должности контакта в компании (через crm_company_contacts.position)
- [ ] Просмотр всех контактов компании на одной странице
- [ ] Редактирование компании
- [ ] Удаление компании (soft delete)
- [ ] Проверка: при удалении компании контакты НЕ удаляются
- [ ] Поиск компании по названию, ИНН, телефону
- [ ] Поиск дублей по ИНН/названию

### 1.3 Связи "Компания-Контакты"
- [ ] Контакт может существовать без компании
- [ ] Контакт может быть привязан к нескольким компаниям
- [ ] При удалении компании связи с контактами разрываются (но контакты сохраняются)
- [ ] История должностей контакта в компаниях

## Блок 2: Управление воронками (Pipelines)

### 2.1 Жизненный цикл воронки
- [ ] Создание воронки в workspace
- [ ] Создание воронки с этапами (минимум 2, максимум 10)
- [ ] Настройка этапов:
  - [ ] Название
  - [ ] Вероятность успеха (0-100%)
  - [ ] Тип этапа (обычный/успех/проигрыш)
  - [ ] Цвет
- [ ] Изменение порядка этапов (drag-and-drop)
- [ ] Редактирование параметров воронки
- [ ] **Архивация пустой воронки** (нет сделок)
- [ ] **Архивация воронки с закрытыми сделками** (won/lost)
- [ ] **Блокировка архивации воронки с активными сделками** (status = 'open')
- [ ] Восстановление архивной воронки
- [ ] Назначение воронки по умолчанию (только одна)

## Блок 3: Управление сделками (Deals)

### 3.1 Создание и базовая навигация
- [ ] Создание сделки в выбранной воронке
- [ ] Автоматическое присвоение первого этапа воронки
- [ ] Привязка к контакту (опционально)
- [ ] Привязка к компании (опционально)
- [ ] Указание бюджета и валюты
- [ ] Назначение ответственного (owner)
- [ ] Указание ожидаемой даты закрытия
- [ ] Добавление описания
- [ ] Указание источника сделки
- [ ] Добавление тегов

### 3.2 Движение по воронке
- [ ] Перемещение сделки на следующий этап (drag-and-drop)
- [ ] Перемещение сделки на предыдущий этап
- [ ] Массовое перемещение нескольких сделок
- [ ] Автоматическое обновление вероятности успеха из этапа
- [ ] Автоматический пересчет прогноза по воронке
- [ ] История перемещений по этапам (аудит)
- [ ] Комментарий при перемещении (опционально)

### 3.3 Закрытие сделок
- [ ] **Успешное закрытие**:
  - [ ] status = 'won'
  - [ ] actual_close_date = текущая дата
  - [ ] Сделка исчезает из активной воронки
  - [ ] Сделка появляется в разделе "Закрытые"
  - [ ] Сохраняется pipeline_id (ссылка на воронку)
- [ ] **Закрытие с проигрышем**:
  - [ ] status = 'lost'
  - [ ] actual_close_date = текущая дата
  - [ ] Поле "Причина отказа" (обязательно/опционально по настройке)
  - [ ] Сделка исчезает из активной воронки
  - [ ] Сохраняется pipeline_id
- [ ] **Реактивация закрытой сделки**:
  - [ ] Возврат в активную воронку
  - [ ] status = 'open'
  - [ ] actual_close_date = NULL
  - [ ] Возврат на тот же этап или в начало воронки (по настройке)

### 3.4 Перенос между воронками
- [ ] Перенос активной сделки в другую воронку
- [ ] При переносе:
  - [ ] Сохраняется история (откуда перенесена)
  - [ ] Сделка помещается на аналогичный этап или первый этап
  - [ ] Предупреждение о возможной потере данных этапа
- [ ] Перенос закрытой сделки (только если сделка реактивирована)
- [ ] История всех переносов доступна в карточке сделки

### 3.5 Фильтрация и поиск сделок
- [ ] Фильтр по статусу (open/won/lost)
- [ ] Фильтр по воронке (pipeline_id)
- [ ] Фильтр по этапу (stage_id)
- [ ] Фильтр по ответственному (owner_id)
- [ ] Фильтр по контакту/компании
- [ ] Фильтр по дате создания/закрытия
- [ ] Фильтр по бюджету (диапазон)
- [ ] Поиск по названию/описанию
- [ ] Сохранение пользовательских фильтров

  - [ ] Встреча (с датой/временем)

### 4.2 Отображение активностей
- [ ] Лента активностей по сделке
- [ ] Лента активностей по контакту
- [ ] Лента активностей по компании
- [ ] Общая лента по workspace (Recent Activity)
- [ ] Фильтр по типу активностей
- [ ] Фильтр по дате
- [ ] Возможность закрепить важную активность (is_important)

### 4.3 Файлы и напоминания
- [ ] Прикрепление файлов к активности
- [ ] Просмотр списка файлов
- [ ] Скачивание файлов
- [ ] Установка напоминания по активности (remind_at)

- [ ] Только автор и админ могут удалять свои активности

  - [ ] Полный доступ ко всем модулям

## Блок 10: Целостность данных и консистентность

### 10.1 Транзакционность
- [ ] При создании сделки + активности всё сохраняется или ничего
- [ ] При перемещении сделки + запись истории - атомарно
- [ ] Нет "битых" ссылок (orphan records)

### 10.2 Каскадные операции
- [ ] При удалении контакта:
  - [ ] Связанные телефоны/email удаляются (CASCADE)
  - [ ] Связи с компаниями удаляются
  - [ ] Сделки НЕ удаляются (owner_id = null или перепривязка)
- [ ] При удалении компании:
  - [ ] Связи с контактами удаляются
  - [ ] Контакты сохраняются
  - [ ] Сделки НЕ удаляются

### 10.3 Аудит
- [ ] Логирование всех изменений (создание, обновление, удаление)
- [ ] Фиксация: кто, когда, что изменил
- [ ] Невозможность подделать историю
- [ ] Хранение изменений минимум 30 дней

## Блок 11: Модульная система (workspace_modules)

### 11.1 Включение/отключение CRM
- [ ] Если CRM отключен в workspace:
  - [ ] Раздел CRM не отображается в меню
  - [ ] API возвращает 403/модуль недоступен
  - [ ] Существующие данные сохраняются (для будущего включения)
- [ ] При включении CRM:
  - [ ] Восстанавливается доступ к данным
  - [ ] Создается воронка по умолчанию (если нет ни одной)

### 11.2 Лицензии пользователей
- [ ] Проверка user_module_licenses при доступе
- [ ] Пользователь без лицензии не видит CRM
- [ ] Разные scope: all_workspaces vs single_workspace

## Критические сценарии (Smoke test)

### Сценарий 1: Полный цикл сделки
1. [ ] Создать контакт "Иван Петров"
2. [ ] Создать компанию "ООО Ромашка"
3. [ ] Привязать контакт к компании
4. [ ] Создать воронку "Продажи услуг" с этапами
5. [ ] Создать сделку "Сайт под ключ" для контакта
6. [ ] Переместить сделку по этапам до финала
7. [ ] Закрыть сделку успешно (won)
8. [ ] Проверить: сделка исчезла из активных, появилась в закрытых
9. [ ] Проверить: в активности есть записи о всех перемещениях
10. [ ] Проверить: в карточке контакта видна закрытая сделка

### Сценарий 2: Удаление/архивация
1. [ ] Создать воронку "Тестовая"
2. [ ] Создать активную сделку в ней
3. [ ] Попытаться удалить воронку → должно быть заблокировано
4. [ ] Закрыть сделку (проигрыш)
5. [ ] Архивировать воронку → должно быть разрешено
6. [ ] Проверить: воронка в архиве
7. [ ] Проверить: закрытая сделка видна в архиве сделок
8. [ ] Проверить: в карточке сделки указана архивная воронка
9. [ ] Восстановить воронку из архива

### Сценарий 3: Права доступа
1. [ ] Создать 2 пользователя: менеджер, руководитель
2. [ ] Создать воронку с правами "только руководитель"
3. [ ] Менеджер пытается зайти → не видит воронку
4. [ ] Руководитель заходит → видит
5. [ ] Создать сделку на руководителя
6. [ ] Переназначить сделку на менеджера
7. [ ] Менеджер теперь видит сделку

## Легенда
- ✅ = Пройдено
- ❌ = Провалено (блокирующее)
- ⚠️ = Провалено (некритичное)
- ⬜ = Не проверено

**Критерий приемки:**
- Все критические проверки (46 шт.) пройдены ✅
- Общий процент успеха ≥ 90%
- Нет блокирующих ошибок (P0)
