## 1. Базовые проверки воронок (pipelines)

### 1.1 Создание воронки
- [ ] Возможно создать воронку с минимальными данми (только название)
- [ ] Возможно создать воронку со всеми заполненными полями:
  - [ ] Название
  - [ ] Описание
  - [ ] Цвет
  - [ ] Иконка
- [ ] Валидация: название обязательно (не пустое)
- [ ] Валидация: максимальная длина названия 255 символов
- [ ] Валидация: спецсимволы в названии обрабатываются корректно
- [ ] Созданная воронка появляется в списке воронок
- [ ] Дата создания воронки корректно сохраняется

### 1.2 Редактирование воронки
- [ ] Возможно изменить название воронки
- [ ] Возможно изменить описание воронки
- [ ] Возможно изменить цвет воронки
- [ ] Возможно изменить иконку воронки
- [ ] Изменения сохраняются и отображаются после обновления страницы
- [ ] Дата обновления (updated_at) меняется при редактировании

### 1.3 Удаление/архивация воронки
- [ ] Нельзя удалить/архивировать воронку с активными сделками (status = 'open')
- [ ] Возможно архивировать пустую воронку (нет сделок)
- [ ] Возможно архивировать воронку только с закрытыми сделками (won/lost)
- [ ] После архивации воронка исчезает из списка активных воронок
- [ ] Архивные воронки отображаются в отдельном разделе/фильтре
- [ ] Возможно восстановить архивную воронку
- [ ] При восстановлении воронка возвращается в активный список
- [ ] В архиве отображается дата архивации и кто архивировал

### 1.4 Воронка по умолчанию
- [ ] Можно отметить воронку как "по умолчанию"
- [ ] Только одна воронка может быть по умолчанию (при выборе новой снимается с предыдущей)
- [ ] При создании новой сделки автоматически подставляется воронка по умолчанию
- [ ] При удалении воронки по умолчанию система предлагает выбрать новую

## 2. Управление этапами (stages)

### 2.1 Создание этапов
- [ ] Возможно добавить этап в воронку
- [ ] Минимальное количество этапов - 2
- [ ] Максимальное количество этапов - 10 (или согласно спецификации)
- [ ] При создании этапа заполняются поля:
  - [ ] Название (обязательно)
  - [ ] Описание (опционально)
  - [ ] Цвет (по умолчанию задан)
  - [ ] Вероятность успеха (по умолчанию, проверка диапазона 0-100)
  - [ ] Тип этапа (обычный/успех/проигрыш)
- [ ] Валидация: вероятность успеха только числа от 0 до 100
- [ ] Валидация: название этапа уникально в рамках воронки

### 2.2 Типы этапов
- [ ] Обычный этап:
  - [ ] Не является финальным
  - [ ] Не является проигрышным
  - [ ] Сделки на этом этапе считаются активными
- [ ] Финальный этап (успех):
  - [ ] Помечен is_final = true
  - [ ] Сделка при переходе становится won
  - [ ] Автоматически заполняется actual_close_date
- [ ] Этап проигрыша:
  - [ ] Помечен is_lost = true
  - [ ] Сделка при переходе становится lost
  - [ ] Обязательно поле "причина отказа" (если настроено)
  - [ ] Автоматически заполняется actual_close_date

### 2.3 Редактирование этапов
- [ ] Возможно изменить название этапа
- [ ] Возможно изменить описание этапа
- [ ] Возможно изменить цвет этапа
- [ ] Возможно изменить вероятность успеха
- [ ] Возможно изменить тип этапа
- [ ] При изменении типа этапа проверяется наличие хотя бы одного финального этапа

### 2.4 Порядок этапов
- [ ] Возможно изменить порядок этапов drag-and-drop
- [ ] После изменения порядка этапы сохраняют новый порядок
- [ ] Сделки не теряют привязку к этапам при изменении порядка
- [ ] Порядок этапов сохраняется при обновлении страницы

### 2.5 Удаление этапов
- [ ] Нельзя удалить этап, на котором есть активные сделки
- [ ] При удалении этапа с закрытыми сделками система запрашивает подтверждение
- [ ] Удаленный этап можно восстановить (если реализовано soft delete)
- [ ] При удалении этапа сделки не удаляются

## 3. Управление сделками (deals)

### 3.1 Создание сделки
- [ ] Создание сделки привязано к воронке (pipeline_id обязателен)
- [ ] При создании автоматически устанавливается первый этап воронки
- [ ] Поля сделки сохраняются корректно:
  - [ ] Название
  - [ ] Контакт/компания
  - [ ] Бюджет
  - [ ] Валюта
  - [ ] Ожидаемая дата закрытия
  - [ ] Ответственный
- [ ] Созданная сделка отображается в канбан-доске на правильном этапе

### 3.2 Перемещение сделок между этапами
- [ ] Возможно переместить сделку на следующий этап (drag-and-drop)
- [ ] Возможно переместить сделку на предыдущий этап
- [ ] При перемещении на финальный этап сделка закрывается (status = won)
- [ ] При перемещении на этап проигрыша сделка закрывается (status = lost)
- [ ] При перемещении автоматически обновляется вероятность успеха (из этапа)
- [ ] Система запрашивает подтверждение при перемещении на финальный этап

### 3.3 Перенос между воронками
- [ ] Возможно перенести сделку в другую воронку
- [ ] При переносе:
  - [ ] Сделка сохраняет историю (откуда перенесена)
  - [ ] Устанавливается на аналогичный этап (по названию/вероятности) или первый этап
  - [ ] Система предупреждает о возможной потере данных
- [ ] История переносов сохраняется и отображается

### 3.4 Закрытие сделок
- [ ] При успешном закрытии:
  - [ ] status = 'won'
  - [ ] actual_close_date = текущая дата
  - [ ] Сделка исчезает из активных воронок
  - [ ] Сделка доступна в архиве/отчетах
- [ ] При проигрыше:
  - [ ] status = 'lost'
  - [ ] actual_close_date = текущая дата
  - [ ] Можно указать причину отказа
  - [ ] Сделка исчезает из активных воронок

### 3.5 Фильтрация сделок
- [ ] Фильтр по статусу:
  - [ ] Все сделки
  - [ ] Активные
  - [ ] Успешные
  - [ ] Проигранные
- [ ] Фильтр по дате:
  - [ ] Сегодня
  - [ ] Неделя
  - [ ] Месяц
  - [ ] Произвольный период
- [ ] Фильтр по этапам
- [ ] Фильтр по ответственному
- [ ] Поиск по названию/контакту

## 4. Права доступа и роли

### 4.1 Уровни доступа к воронкам
- [ ] Просмотр (view): только видит сделки
- [ ] Редактирование (edit): может создавать/изменять сделки
- [ ] Администрирование (admin): может изменять настройки воронки

### 4.2 Проверка прав
- [ ] Пользователь без прав не видит воронку
- [ ] Пользователь с правами просмотра не может создавать сделки
- [ ] Пользователь с правами редактирования может создавать/изменять сделки
- [ ] Пользователь с правами редактирования НЕ может изменять настройки воронки
- [ ] Администратор может изменять все настройки воронки
- [ ] Администратор может удалять/архивировать воронку
- [ ] Владелец workspace имеет полный доступ ко всем воронкам

### 4.3 Назначение прав
- [ ] Возможно назначить права на воронку для конкретного пользователя
- [ ] Возможно назначить права на воронку для роли (менеджер, директор и т.д.)
- [ ] Изменения прав вступают в силу немедленно
