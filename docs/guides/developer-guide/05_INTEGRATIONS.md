# Гайд разработчика: Возможности интеграций

**Цель:** Обзор точек интеграции, внешних сервисов и возможностей расширения backend.

---

## 1. Уже реализованные интеграции

| Интеграция | Назначение | Реализация |
|------------|------------|------------|
| **PostgreSQL** | Основная БД | `database/sql` + GORM |
| **Redis** | Realtime Pub/Sub | `pkg/realtime/redis.go`, каналы `ws:workspace:{id}`, `ws:user:{id}` |
| **SMTP** | Email | `pkg/email/smtp.go` — приглашения, верификация |
| **JWT** | Аутентификация | `pkg/auth/token/token.go` |
| **Casbin** | RBAC | GORM-адаптер, таблица `casbin_rule` |

### 1.1. Конфигурация (config)

```go
// Переменные окружения
DB_*           // PostgreSQL
REDIS_URL      // Redis (опционально)
JWT_SECRET_KEY, JWT_EXPIRATION
EMAIL_*        // SMTP (SMTPHost, SMTPPort, ...)
SERVER_HOST, SERVER_PORT
```

## 3. Точки расширения в коде

### 3.1. Email

```go
// pkg/email/sender.go
type Sender interface {
    SendInviteEmail(...) error
    SendVerificationEmail(...) error
}
// Реализации: SMTPSender, NoopSender
```

**Расширение:** Добавить SendGrid, AWS SES, Resend — реализовать интерфейс `Sender`.

### 3.2. Realtime

```go
// pkg/realtime/publisher.go
type Publisher interface {
    Publish(channel string, payload []byte) error
}
// Реализации: RedisPublisher, NoopPublisher
```

**Расширение:** WebSocket-сервер, который подписывается на Redis и отдаёт события клиентам.

### 3.3. Хранилище файлов

Сейчас файлы (вложения, аватары) — через локальную файловую систему или не реализованы.

**Расширение:** S3-совместимое хранилище (MinIO, AWS S3), интерфейс `FileStorage`.

### 3.4. Очереди задач

Сейчас нет отдельной очереди. Логи обрабатываются воркером `LogProcessor`.

**Расширение:** RabbitMQ, Redis Queue, AWS SQS — для асинхронной отправки email, тяжёлых задач.

## 4. API для внешних интеграций

### 4.1. Текущий API

- REST на Gin
- JWT в cookie `access_token` или заголовке `Authorization`
- Базовый путь: `/api/v1`

### 4.2. Webhooks (планируется)

События для подписчиков:
- `task.created`, `task.completed`
- `deal.updated`, `deal.stage_changed`
- `invitation.accepted`

**Реализация:** Таблица `webhook_subscriptions`, воркер при событии — POST на URL подписчика.

### 4.3. Open API (планируется)

- Публичный API для партнёров
- API-ключи вместо JWT
- Ограничение по rate limit

## 5. Интеграция по модулям

### 5.1. CRM

| Что интегрировать | Как |
|-------------------|-----|
| Контакты из amoCRM | Импорт через API, маппинг полей |
| Звонки | SIP-события → crm_activities (type=call) |
| Мессенджеры | Webhook от провайдера → crm_activities |

### 5.2. Tasks

| Что интегрировать | Как |
|-------------------|-----|
| Trello/Asana | Импорт через их API |
| Календарь (Google, Outlook) | Sync через CalDAV или API |
| Напоминания | Push (FCM), Telegram Bot API |

### 5.3. Finance (будущий)

| Что интегрировать | Как |
|-------------------|-----|
| Банки | Open Banking API, выписки |
| ЭДО | Диадок, СБИС API |
| Налоговые | ФНС API (при наличии) |

## 6. Безопасность интеграций

| Аспект | Рекомендация |
|--------|--------------|
| API-ключи | Хранить в env, не в коде |
| Webhooks | Подпись (HMAC), проверка на стороне подписчика |
| Rate limiting | По IP, по user_id, по API key |
| CORS | Настроить для фронта и доверенных доменов |
