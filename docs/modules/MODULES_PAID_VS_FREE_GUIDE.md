# Гайд: платные и бесплатные модули

Как настроить модуль как бесплатный, платный или с триалом по умолчанию.

---

## 1. Типы модулей

| Тип | is_core | default_trial_days | Поведение |
|-----|---------|-------------------|------------|
| **Всегда бесплатен** | TRUE | — | Tasks, Habits. Доступен всем, лицензия не нужна. |
| **Триал по умолчанию** | FALSE | 30 | CRM, Projects. Новые workspace получают 30 дней триала. |
| **Платный по умолчанию** | FALSE | NULL или 0 | Нужна лицензия для включения. |

---

## 2. Сделать модуль всегда бесплатным (как Tasks)

```sql
UPDATE modules SET is_core = TRUE WHERE code = 'tasks';
```

- Триггер при создании workspace добавляет модуль со status = `active`.
- Лицензия не проверяется.
- Модуль нельзя «отключить» в смысле оплаты — он всегда доступен.

---

## 3. Сделать модуль платным (с триалом по умолчанию)

**Сейчас (все с триалом):**
```sql
UPDATE modules SET default_trial_days = 30 WHERE code = 'crm';
```

**Новый модуль — сразу платный, без триала:**
```sql
INSERT INTO modules (id, code, name, description, is_core, default_trial_days)
VALUES (gen_random_uuid(), 'new_module', 'Новый модуль', '...', FALSE, NULL);
-- или default_trial_days = 0
```

---

## 4. Перевести бесплатный модуль в платный

**Было:** модуль бесплатен (is_core = TRUE или default_trial_days > 0).

**Шаги:**

1. Убрать core и триал:
```sql
UPDATE modules SET is_core = FALSE, default_trial_days = NULL WHERE code = 'crm';
```

2. Триггер перестанет добавлять модуль в новые workspace.
3. Существующие workspace сохраняют записи в `workspace_modules` — доступ остаётся.
4. Новые workspace не получат модуль автоматически — нужна лицензия.

**Важно:** уже выданные триалы/лицензии в `workspace_modules` не трогаются. Отключение — только через UI (владелец нажимает «Отключить»).

---

## 5. Перевести платный модуль в бесплатный

```sql
UPDATE modules SET is_core = TRUE WHERE code = 'crm';
```

- Новые workspace получат модуль автоматически.
- Существующие workspace — без изменений (у кого уже есть — остаётся).

---

## 6. Изменить длительность триала по умолчанию

```sql
-- 14 дней вместо 30
UPDATE modules SET default_trial_days = 14 WHERE code = 'crm';
```

Влияет только на **новые** workspace. Уже созданные триалы не меняются.

---

## 7. Админ-панель: управление триалом

- **Модули** рядом с workspace → модалка модулей.
- Действия: **+30 дн** (продлить), **Триал** (добавить, если отключён), **Full** (полная лицензия).

API: `PATCH /admin/workspaces/:id/modules/:code` с телом:
```json
{ "action": "extend_trial"|"add_trial"|"set_full", "trialDays": 30 }
```

---

## 8. Сводка

| Цель | Действие |
|------|----------|
| Модуль всегда бесплатен | `is_core = TRUE` |
| Модуль с триалом для новых workspace | `is_core = FALSE`, `default_trial_days = 30` |
| Модуль платный, без триала | `is_core = FALSE`, `default_trial_days = NULL` |
| Продлить триал вручную | Админка → Модули → +30 дн |
| Выдать полную лицензию | Админка → Модули → Full |
